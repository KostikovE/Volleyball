# Архитектура веб-системы для автоматического анализа волейбольных видео

## 1. Назначение системы

Система предназначена для автоматического анализа волейбольных видео. Пользователь загружает запись матча, после чего система самостоятельно находит игровые эпизоды (розыгрыши) и формирует список с указанием времени начала и окончания каждого розыгрыша, а также стороны, выполнившей подачу.

Исходные данные проекта — одна запись волейбольного матча длительностью около 21 минуты.

---

## 2. Состав системы

Система включает несколько компонентов, каждый из которых выполняет отдельную задачу.

| Компонент                 | Назначение |
|---------------------------|--------------------------------------------------------------------|
| Frontend (React)          | Интерфейс пользователя: загрузка видео, просмотр списка розыгрышей |
| Backend (FastAPI)         | Приём видео, обработка запросов, взаимодействие с базой данных |
| База данных (SQLite)      | Хранение информации о пользователях, видео, задачах и розыгрышах |
| Очередь задач (Redis)     | Хранение задач, ожидающих обработки |
| Worker (Celery)           | Выполнение обработки видео в фоновом режиме |
| Нейросеть (YOLO + трекер) | Обнаружение объектов на видео: мяча, игроков, судьи |
| Файловое хранилище        | Хранение видеофайлов и результатов работы нейросети |
| Docker Compose            | Запуск всех компонентов системы |


Пользователь загружает видео через браузер. Backend сохраняет файл и регистрирует задачу в очереди. Worker извлекает задачу, выполняет обработку с помощью нейросети и сохраняет найденные розыгрыши в базу данных. После завершения обработки пользователь получает доступ к результатам.

---

## 3. Хранение данных

В системе используются три типа хранилищ, каждое из которых предназначено для определённого вида данных.

### 3.1. Видеофайлы

Видеофайлы сохраняются в папке `data/uploads/`. База данных не используется для хранения больших файлов, поэтому в ней сохраняется только путь к видео.

### 3.2. Результаты работы нейросети

Результаты обнаружения объектов на каждом кадре сохраняются в папке `data/artifacts/` в виде отдельных файлов. Эти данные имеют большой объём и используются преимущественно для отладки и повторного анализа. В базе данных сохраняется ссылка на соответствующий файл.

### 3.3. Найденные розыгрыши

Найденные розыгрыши сохраняются в базе данных. Это итоговый результат работы системы, который отображается пользователю. Данные структурированы и имеют небольшой объём, что позволяет эффективно выполнять выборки и сортировку.

### 3.4. Служебная информация

Сведения о пользователях, загруженных видео и задачах обработки также хранятся в базе данных.

## 4. Обоснование выбора способа хранения

В ходе проектирования были рассмотрены три варианта хранения результатов работы нейросети.

### Вариант 1. Хранение всех данных в базе данных

Каждый обнаруженный объект сохраняется отдельной записью. При обработке одного видео формируется несколько сотен тысяч записей.

Основные недостатки: значительный рост размера базы данных, длительная запись, возникновение конфликтов при одновременном чтении и записи.

### Вариант 2. Хранение данных в файлах со ссылками в базе данных

Результаты работы нейросети сохраняются в отдельных файлах, а в базе данных хранится только путь к ним.

Основные преимущества: высокая скорость записи, компактность базы данных, возможность повторного анализа и отладки. Недостаток — необходимость контроля соответствия между файлами и записями в базе.

### Вариант 3. Хранение только итоговых розыгрышей

Результаты работы нейросети не сохраняются, в базе данных остаются только найденные розыгрыши.

Основной недостаток: невозможность повторного анализа без повторной обработки видео.

### Выбранный вариант

Принят гибридный подход. Результаты работы нейросети сохраняются в файлах, итоговые розыгрыши — в базе данных. Ссылка на файл с результатами хранится в базе. Таблицы для хранения результатов обнаружения присутствуют в схеме, но по умолчанию не заполняются.

Такой подход обеспечивает высокую скорость обработки, компактность базы данных, сохранение исходных данных для отладки и возможность дальнейшего развития системы.

## 5. Структура базы данных

База данных включает четыре основные таблицы.

### Таблица `users`

| Поле | Назначение |
|---|---|
| id | Уникальный идентификатор пользователя |
| email | Электронная почта |
| password_hash | Хеш пароля |
| created_at | Дата регистрации |

### Таблица `videos`

| Поле | Назначение |
|---|---|
| id | Уникальный идентификатор видео |
| user_id | Идентификатор пользователя, загрузившего видео |
| filename | Путь к файлу |
| duration | Длительность видео |
| fps | Частота кадров |
| width, height | Разрешение видео |
| status | Текущий статус обработки |
| created_at | Дата загрузки |

Статусы видео: `uploaded`, `queued`, `processing`, `completed`, `error`.

### Таблица `processing_jobs`

| Поле | Назначение |
|---|---|
| id | Уникальный идентификатор задачи |
| video_id | Идентификатор видео |
| status | Статус задачи |
| progress | Прогресс обработки в процентах |
| artifact_path | Путь к файлу с результатами обнаружения |
| started_at | Время начала обработки |
| finished_at | Время завершения обработки |

### Таблица `rallies`

| Поле | Назначение |
|---|---|
| id | Уникальный идентификатор розыгрыша |
| video_id | Идентификатор видео |
| number | Порядковый номер розыгрыша |
| start_time | Время начала |
| end_time | Время окончания |
| start_frame | Номер начального кадра |
| end_frame | Номер конечного кадра |
| serve_side | Сторона подачи |

Значения поля `serve_side`: `unknown`, `near`, `far`.

## 6. Процесс обработки видео

Обработка видео проходит следующие этапы.

1. Пользователь загружает видеофайл через интерфейс.
2. Backend сохраняет файл и извлекает его основные характеристики.
3. В базе данных создаются записи о видео и задаче обработки.
4. Задача помещается в очередь.
5. Worker извлекает задачу и приступает к обработке.
6. Нейросеть выполняет обнаружение объектов на каждом кадре.
7. Результаты обнаружения сохраняются в файл.
8. Выполняется анализ результатов и определение границ розыгрышей.
9. Найденные розыгрыши сохраняются в базе данных.
10. Статус видео изменяется на «обработано».

---

## 7. Обработка ошибок

При возникновении ошибок во время обработки система фиксирует соответствующий статус для видео и задачи. Пользователь получает уведомление о неудачной обработке. Предусмотрена возможность автоматического повторения задачи.

---

## 8. Повторная обработка

При повторной обработке одного и того же видео ранее сохранённые розыгрыши удаляются, после чего формируются новые. Это исключает появление дублирующихся записей.
